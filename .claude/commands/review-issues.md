Propose a next step for working on this project.

Please follow the "Review, Categorize, Update, Plan, Propose" workflow when you start.

# Review

Review the open tickets in Github.

# Categorize.

Use parallel subagents to ensure that they're all labled appropriately. Tickets
should be labled with the component(s) affected, an estimated level of effort
(low, medium, complex), an estimated level of impact, and whether it's fixing a
bug or a new enhancement.

Update any ticket that is not labled appropriately.

If there are things you still do not understand or questions you have for the
user, pause here to ask them before continuing.

# Update

Next use parallel subagents to review the code, and docuentation for any work
that should be done but isn't yet in a ticket. Skipped tests, unimplmented, or
stubbed features, and comments suggesting future work all count here. Create a
separate ticket for each piece of work not yet completed and not yet
represented by a ticket.

If there are things you still do not understand or questions you have for the
user, pause here to ask them before continuing.

# Plan

Next use a subagent to think hard about the existing tickets and write up a
detailed roadmap for delivery. If there are things you're not sure about, use
parallel subagents to do some web research. They should return only useful
information, no noise.

If there are things you still do not understand or questions you have for the
user, pause here to ask them before continuing.

# Propose

Review the roadmap, focus on impact and issue complexity. Propose the next
ticket or tickets that should be worked on to form a single PR.

Include a brief justification for why these tickets should be next,
alternatives you reviewed,  and an estimate in LLM tokens.
